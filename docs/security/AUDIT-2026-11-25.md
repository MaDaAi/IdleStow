# Security, privacy and launch audit — IdleStow 0.1.0

## Overview

- **Project:** IdleStow, a Windows desktop application (Java 21 / JavaFX, Python 3.12 worker, SQLite) that compresses inactive local files.
- **Inspected:** source repository (`main`, audit date 2026-11-25), full git history, CI workflows, build/packaging scripts, the locally built Windows package (`dist/windows/IdleStow`).
- **Not inspected:** live GitHub account settings (2FA, branch protection, private vulnerability reporting), GitHub Actions run results, any machine other than the Windows 11 development PC.
- **Threat model:** see `docs/security/threat-model.md`. There are no servers, accounts, payments, cookies or AI features. The relevant risks are local data integrity, path and link escapes, archive parsing, the subprocess/IPC boundary, dependencies and the supply chain.
- **Highest remaining risks:** unverified GitHub account 2FA (55); no recorded maintainer line-by-line review of safety-critical code (50); unsigned release binaries (platform section).
- **Verdict:** **CONDITIONALLY READY**. See Readiness.

## Readiness

**CONDITIONALLY READY** for a public open-source 0.1.0 release on Windows. No confirmed security failures remain. Before release, the owner should:

1. Enable two-factor authentication on the GitHub account (check 55).
2. Enable branch protection on `main` and private vulnerability reporting.
3. Personally review the safety-critical modules: `core/jobs`, `Authorizer`, the Windows adapter (check 50).
4. Publish SHA-256 checksums with release downloads (unsigned binaries).
5. Optionally, run a manual accessibility pass and a trademark search.

No checklist guarantees immunity from attacks or legal claims.
